# Hybrid Cloud SOC Implementation Guide: Microsoft Sentinel & Azure Arc

## 1. Project Overview & Objectives
This project demonstrates how to construct a zero-compute-cost enterprise hybrid Security Operations Center (SOC) using:
- **Microsoft Sentinel** (Cloud-native SIEM/SOAR)
- **Azure Arc** (Hybrid Resource Projection)
- **Azure Monitor Agent (AMA)** (Unified Data Ingestion Pipeline)
- **Physical Windows 11 Endpoint (`LAPTOP-0INKSJEM`)**

---

## 2. Infrastructure Deployment Details

### Subscription & Resource Group
- **Subscription**: Azure for Students
- **Resource Group**: `LAB`
- **Location**: `East Asia` (`eastasia`)
- **Log Analytics Workspace**: `Lab-1`
- **SIEM Engine**: Microsoft Sentinel onboarded onto `Lab-1`

### Azure Arc Agent Installation & Configuration
- **Agent**: `azcmagent` v1.68
- **Command Used**:
  ```powershell
  & "$env:ProgramW6432\AzureConnectedMachineAgent\azcmagent.exe" connect `
      --resource-group "LAB" `
      --tenant-id "<TENANT_ID>" `
      --location "eastasia" `
      --subscription-id "<SUBSCRIPTION_ID>" `
      --cloud "AzureCloud" `
      --enable-automatic-upgrade
  ```
- **Troubleshooting Note**: Attempting deployment to `centralindia` failed due to Azure Policy restriction (`RequestDisallowedByAzure: 403`). Aligning the Arc resource location to `eastasia` (where `Lab-1` resides) resolved the policy constraint immediately.

## 4. Adversary Simulation Playbook

### Attack Scenario 1: Password Spray / Brute Force (T1110)
```powershell
1..5 | ForEach-Object {
    net use \\127.0.0.1\c$ /user:AttackerAccount WrongPass!$_ 2>$null
}
```
*Generates 5 distinct 4625 events (An account failed to log on).*

### Attack Scenario 2: Persistence via Rogue Account Creation (T1136.001)
```powershell
net user BackdoorUser P@ssw0rd2026! /add
net user BackdoorUser /delete
```
*Generates Event ID 4720 (User Account Created) and Event ID 4726 (User Account Deleted).*

## 5. Detection Engineering & Analytics Rules

### Rule 1: Multiple Failed Windows Logons
- **Query**:
  ```kql
  SecurityEvent
  | where EventID == 4625
  | summarize FailedCount = count() by Account, Computer, IpAddress
  | where FailedCount >= 3
  ```
- **Severity**: Medium
- **Tactics**: Credential Access (T1110)
- **Evaluation**: Every 5 minutes, 1-hour lookback window.

### Rule 2: Rogue Backdoor Account Creation
- **Query**:
  ```kql
  SecurityEvent
  | where EventID == 4720
  | project TimeGenerated, TargetAccount, SubjectUserName, Computer, Activity
  ```
- **Severity**: High
- **Tactics**: Persistence (T1136.001)
- **Evaluation**: Every 5 minutes, 1-hour lookback window.

## 6. SOAR Automation Rule Configuration
- **Rule Name**: `Auto-Triage-Endpoint-Incidents`
- **Trigger**: When incident is created
- **Actions**:
  - Automatically tags incidents with `Hybrid-Lab`, `Windows-Endpoint`, `Triage-Required`
  - Sets incident lifecycle state to `Active`

## 7. Verification & Incident Investigation
1. Navigate to **Microsoft Sentinel $\rightarrow$ Incidents**.
2. Identify the active incidents generated by the scheduled rules.
3. Open the **Investigation Graph** to visualize the relationship between:
   - Affected Host (`LAPTOP-0INKSJEM`)
   - Targeted Account (`AttackerAccount`, `BackdoorUser`)
   - Attacker IP (`127.0.0.1`)
   - Correlated Alert Timeline
